# 🟣 Cells.io

Багатокористувацька гра у стилі agar.io. Node.js + WebSocket на сервері, чистий Canvas на клієнті, без збірки й без залежностей, окрім `ws`.

- З'їдай їжу та менших гравців, тікай від більших
- Онлайн-мультиплеєр: усі гравці на одному сервері бачать одне одного
- Світла й темна тема (кнопка 🌙/☀️ внизу праворуч, вибір зберігається)
- Клітина може частково виходити за край мапи, тож у кутку сховатись не вийде
- Боти заповнюють порожню мапу й відступають, коли приходять живі гравці

## Запуск локально

```bash
npm install
npm start
# відкрий http://localhost:3000 (у кількох вкладках або з кількох пристроїв у одній мережі)
```

Змінні середовища: `PORT` (за замовчуванням 3000), `MAX_PLAYERS` (за замовчуванням 80).

## Як запустити в онлайні

GitHub сам по собі такий сервер не запускає (він віддає лише статику). Тому потрібен хостинг із Node.js, а на GitHub лежить код.

### Варіант 1: Render.com (безкоштовно, найпростіше)
1. Зареєструйся на render.com і підключи GitHub.
2. **New + → Blueprint** → вибери репозиторій. `render.yaml` усе налаштує сам.
   (Або **New + → Web Service**: Build `npm install`, Start `npm start`.)
3. Через пару хвилин отримаєш адресу `https://cells-io-xxxx.onrender.com`. Це і є гра. Кидай посилання друзям.

На безкоштовному плані сервіс засинає після ~15 хв без відвідувачів, перший вхід після сну триває близько хвилини.

### Варіант 2: Railway / Fly.io / Koyeb / будь-який Docker-хостинг
У репозиторії є `Dockerfile`. Хостинг підхопить його сам, порт береться зі змінної `PORT`.

### Варіант 3: власний VPS
```bash
git clone https://github.com/<логін>/cells-io.git && cd cells-io
npm install
PORT=80 npm start        # краще під pm2 або systemd, з HTTPS через Caddy/nginx
```
Для WebSocket за reverse proxy треба передавати заголовки Upgrade (Caddy робить це автоматично).

### Лише клієнт на GitHub Pages (необов'язково)
Pages віддає тільки статику, тому сервер має працювати деінде (наприклад на Render). Тоді:
1. У `public/config.js` пропиши `window.GAME_SERVER = "wss://cells-io-xxxx.onrender.com/ws";`
2. Settings → Pages → Source: **GitHub Actions**, потім Actions → *Deploy client to GitHub Pages* → Run workflow.

Без сервера гра на Pages працює в офлайн-режимі з ботами. Адресу сервера можна передати і в посиланні: `…/?server=wss://host/ws`.

## Як це влаштовано

- `server.js`: віддає `public/`, приймає WebSocket на `/ws`, перевіряє й обмежує вхідні дані, 20 разів на секунду розсилає кожному гравцю лише тих, хто поблизу, раз на секунду розсилає топ-8.
- `public/index.html`: уся гра (рендер, керування, боти, теми).
- Положення й масу кожен клієнт рахує сам, сервер це довіряє. Це нормально для гри з друзями, але не захищає від чит-клієнтів. Для публічного проєкту знадобиться авторитетний сервер.
- Їжа розкладена однаково в усіх (за seed), але з'їдена зникає лише у того, хто її з'їв.
- `GET /healthz` повертає `ok` (для перевірки хостингу).
